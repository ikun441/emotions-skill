## 1. 项目背景

当前 AI 对话助手在情绪表达上存在"扁平化"问题：无论用户情绪如何起伏，AI 的回复风格始终一致，缺乏人格连续性与情绪记忆。这导致长对话中用户难以建立情感连接，AI 显得"机械"。

**emotions-skill** 致力于为 AI 注入可持久化的"人格 + 情绪"状态机，使 AI：

1. 拥有稳定且可量化的人格画像（基于大五人格 / 九型人格 / MBTI 三种模型）；
2. 在每轮对话后，依据本轮交互内容更新情绪数值；
3. 在下一轮对话前，读取历史情绪与人格类型，生成与之匹配的个性化回复风格。

核心价值：**让 AI 的情绪"拟人化"且"有记忆"**。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 验收方式 |
|------|------|----------|
| G1 | 支持三种人格模型的建立、存储与读取 | 单元测试覆盖三种模型的序列化/反序列化 |
| G2 | 每轮对话后输出可解释的情绪变化 Δ | 输出包含 `emotion_delta` 与触发原因 |
| G3 | 情绪状态跨对话持久化 | 重启后读取档案，情绪数值连续 |
| G4 | 基于人格 + 情绪生成回复风格调制指令 | 输出 `style_directive` 供 LLM 使用 |
| G5 | 作为标准 CodeArts Skill 可被加载与上传 | 通过 `uploadUserSkillToHuawei` 成功上传 |

### 2.2 非目标

- 不替代底层 LLM，仅输出"风格调制指令"与"情绪上下文"，由宿主 LLM 据此生成最终回复；
- 不做实时语音情绪识别（v1 仅文本）；
- 不做多人格多用户管理系统（v1 单档案为主，预留多档案接口）；
- 不做医疗/心理咨询诊断。

## 4. 功能需求

### FR-1 人格档案管理

| 需求 | 说明 |
|------|------|
| FR-1.1 | 支持通过简短问卷（或默认值）初始化人格档案 |
| FR-1.2 | 支持三种模型独立配置：大五人格（5 维度 0–1）、九型人格（主型 1–9 + 翼型 + 健康水平）、MBTI（16 型 + 4 维度倾向值） |
| FR-1.3 | 档案持久化为 JSON 文件，路径可配置 |
| FR-1.4 | 支持读取、更新、重置档案 |

### FR-2 情绪状态机

| 需求 | 说明 |
|------|------|
| FR-2.1 | 情绪状态采用双表征：连续 PAD 模型（愉悦度/唤醒度/支配度）+ 离散基本情绪（Ekman 六情绪） |
| FR-2.2 | 每轮对话前执行情绪衰减（向人格基线收敛） |
| FR-2.3 | 每轮对话后依据用户输入情绪信号 + 人格调制系数计算 Δ |
| FR-2.4 | 记算结果写回档案并追加到 `history` |

### FR-3 情绪感知

| 需求 | 说明 |
|------|------|
| FR-3.1 | 从用户文本提取情绪信号（关键词词典 + 可选语义分析） |
| FR-3.2 | 输出结构化情绪信号：`{valence, arousal, dominant_emotion, intensity, triggers}` |

### FR-4 个性化回复调制

| 需求 | 说明 |
|------|------|
| FR-4.1 | 依据人格类型 + 当前情绪，生成 `style_directive`（语气/用词/长度/emoji 倾向/共情强度） |
| FR-4.2 | 输出可直接拼接至 LLM system prompt 的中文指令片段 |

### FR-5 Skill 封装

| 需求 | 说明 |
|------|------|
| FR-5.1 | 以 `SKILL.md`（frontmatter + 工作流）为核心，`references/` 存放算法说明 |
| FR-5.2 | `scripts/` 存放可执行算法实现（Python），供 Skill 调用 |
| FR-5.3 | 可通过 `uploadUserSkillToHuawei` 上传至华为云 Skills Marketplace |

---

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单轮情绪更新 < 50ms（纯算法，不含 LLM 调用） |
| 可解释性 | 每次 Δ 输出必须附带触发原因与调制系数 |
| 可复现性 | 相同输入 + 相同档案 → 相同输出（确定性算法，v1 不引入随机） |
| 持久化 | JSON 单文件，原子写入（写临时文件后 rename） |
| 可移植性 | 算法核心纯 Python 标准库实现，无重型依赖 |
| 安全性 | 不存储用户对话原文明文长期留存（history 仅存摘要/情绪向量，可配置） |

---

## 6. 验收标准（Done When）

1. 三种人格模型均可建立并持久化，重启后可完整恢复；
2. 连续 3 轮对话后，`history` 中有 3 条记录，每条含 `emotion_delta` 与 `reason`；
3. 情绪衰减可观测：无刺激间隔后，情绪向量向基线收敛；
4. 不同人格对相同刺激产生不同 Δ（如高神经质者负面刺激 Δ 更大）；
5. `style_directive` 在 INFJ 与 ESTP 两种人格下输出明显不同；
6. Skill 目录可被 `uploadUserSkillToHuawei` 成功上传。
